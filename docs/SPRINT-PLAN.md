# Sprint plan: Deals UI

Three sprints. Each sprint has a goal and a committed set of tickets from the [backlog](backlog/README.md). How the team orders and splits the work inside a sprint is the team's decision.

| | Sprint 1 | Sprint 2 | Sprint 3 |
|---|---|---|---|
| **Goal** | A signed-in rep can find any customer and see the whole relationship | Reps run their own pipeline in the CRM, and Priya has her Monday number | Priya manages the data herself, the app is tested, and we release |
| **Tickets** | NIM-100 to 104, NIM-110 to 114 | NIM-120 to 125 | NIM-130 to 134, NIM-140 to 142 |
| **Points** | 29 | 24 | 28 (NIM-134 is a stretch goal) |
| **Demo to Priya** | Sign in as a rep; find Nadia Fenwick; open her profile and her company | Aisha works her pipeline; Priya reads her Monday number | Priya creates a deal for Ben; Ben finds it; test evidence; release notes |

## Ceremonies

| When | What | Output |
|---|---|---|
| Sprint start | Planning: confirm the goal, pull tickets, raise questions for Priya | The sprint's tickets with an owner each |
| Daily | Stand-up: done, next, blocked | Blockers raised the same day |
| Mid-sprint | Backlog refinement: read the next sprint's tickets, list your questions | Questions sent to Priya and the backend team |
| Sprint end | Review: demo working software against the acceptance criteria | Accepted or rejected per ticket |
| Sprint end | Retrospective | One thing to change next sprint |

## Rules

- **NIM-100 (the specification) is finished before any screen ticket starts.**
- A ticket is "in progress" only when someone owns it and has a branch for it.
- A ticket is "done" only when its acceptance criteria are shown working against the real API and the [definition of done](KT-HANDOVER.md#11-how-we-work-together) is met.
- Questions go to Priya (product) or the backend team (API) in writing, with evidence. Record the answers in the spec.
- A ticket that is not done at the end of a sprint goes back to the backlog, with a note on what remains. It is never marked done "except for tests".
